## 1. 사람이 해야 하는 일 — 키체인 등록 2건

에이전트는 **읽는 코드까지만** 바꾼다. 등록은 사람이 한다.

KIS 는 `app_key`·`app_secret` 이 쌍으로 발급되므로 **항목 하나에 둘을 담는다.** `krx_auth.py` 가 이미 쓰는 방식이다(`acct` 에 ID, `-w` 에 PW).

```bash
# ① KIS — acct=app_key, 비밀번호=app_secret
security add-generic-password -U -s wst-kis -a "<APP_KEY>" -w "<APP_SECRET>"

# ② Anthropic — acct 는 고정, 비밀번호=api_key
security add-generic-password -U -s wst-anthropic -a sjbossa -w "<ANTHROPIC_API_KEY>"
```

> `-U` 는 기존 항목이 있으면 갱신한다. 값이 셸 히스토리에 남는 것이 싫으면 `-w` 를 값 없이 주면 대화형으로 입력받는다.

### 등록 확인 (값 미출력)

```bash
security find-generic-password -s wst-kis       -w >/dev/null 2>&1 && echo "wst-kis OK"
security find-generic-password -s wst-anthropic -w >/dev/null 2>&1 && echo "wst-anthropic OK"
```

### 2-1. 읽는 쪽 — `notifier.py` 패턴을 따른다 (하드 페일)

**KIS·Anthropic 은 폴백이 없다** — 키가 없으면 수집도 보고서 생성도 못 한다. 따라서 `notifier.py` 의 하드 페일 패턴을 쓰고, 에러 메시지에 §1 의 등록 명령을 그대로 넣는다.

`reporter.py` 는 `anthropic` · `openai` · `google` 세 provider 를 분기한다(`_call_ai:516`). 지금 `config.yaml` 은 `provider: anthropic` 이지만, "환경변수 3개가 다 있어야 부팅" 같은 규칙을 걸면 provider 를 바꾸는 순간 부팅이 막힌다.

### 2-4. launchd plist 도 함께 바꾼다

`~/Library/LaunchAgents/com.weeklystocks.pipeline.plist` 는 **로그인 셸 환경을 상속하지 않는다.** plist 를 안 고치면 대화형 실행만 되고 무인 실행이 조용히 죽는다.

현재 `ProgramArguments` 는 `bash -c` 한 줄이므로, 그 안에서 `security` 를 호출해 주입하거나 — 코드가 직접 키체인을 읽게 만들었다면 아무것도 안 해도 된다. **2-1 을 코드 내부 읽기로 구현하면 plist 변경이 불필요하다.** 그 편이 진입점이 하나 줄어 안전하다.

## 3. 로그 관측성 — 함께 처리 (범위 축소됨)

키 이관 직후가 가장 위험한 구간이므로 관측성을 같이 본다. 다만 **당초 진단보다 문제가 작다.** 실측 결과:

```
main.py:26   logging.FileHandler("pipeline.log")   ← mode='a' (append), 기본값
             → pipeline.log  274KB · 2026-03-01 ~ 2026-08-21 · 타임스탬프 있음 · gitignore 등록
plist        bash -c "... > /tmp/weeklystocks_pipeline.log 2>&1"
             → 매 실행 덮어씀 · /tmp 라 재부팅에 소실
```

| 로그 | 무엇이 담기나 | 상태 |
|------|---------------|------|
| `pipeline.log` (리포 루트) | `basicConfig` 이후의 모든 로그. 시각 포함 | **정상 — 손댈 것 없음** |
| `/tmp/weeklystocks_pipeline.log` | stdout/stderr 전량. 특히 **`basicConfig` 이전에 죽은 경우의 트레이스백** | 주 1회 덮어쓰기 + 휘발 |
| `pipeline_err.log` (리포 루트) | 없음. 2026-03-20 이후 0바이트 | **죽은 파일 — 삭제 대상** |

즉 진짜 공백은 **"로깅이 서기 전에 죽은 경우"** 한 가지다. 그리고 그것이 정확히 키체인 이관이 새로 만드는 실패 모드다 — 키를 못 읽어 import·초기화 단계에서 예외가 나면 `pipeline.log` 에는 한 줄도 안 남고 `/tmp` 사본만 남으며, 그마저 다음 주 실행이 덮어쓴다.

**조치:** plist 의 리다이렉트를 `>> <리포>/pipeline_boot.log 2>&1` 로 바꾼다. `pipeline.log` 는 그대로 둔다(포맷·경로 모두 정상). `pipeline_err.log` 는 삭제한다.

> 로테이션: `pipeline.log` 는 6개월에 274KB(월 ~50KB) 라 당장 필요 없다. 필요해지면 `RotatingFileHandler` 로 바꾼다.

### SJAIINV-48(UTC ISO-8601) 과의 관계

MacroTracker 가 확정한 규격은 **UTC ISO-8601 · 줄 앞 · 정의는 한 곳 · 시각 주입 고정 가능 · 기존 본문 보존** 이다. WST 는 이미 `basicConfig` 한 곳에서 시각을 붙이고 있으므로 **포맷 문자열 한 줄**로 맞출 수 있다. 다만 현재 형식이 로컬시각(`2026-08-21 20:14:06,443`)이라 UTC 로 바꾸면 과거 로그와 섞인다 — 이관과 같은 커밋에 넣지 말고 별도로 처리한다.

## 4-1. ⚠️ 배포 순서 — 이 순서를 어기면 금요일 잡이 죽는다

`modules/secrets.py` 는 **키체인에서만** 읽는다. config 평문 폴백이 없다(`notifier.py` 와 같은 정책). 따라서 **키체인 등록이 코드 배포보다 먼저**여야 한다.

launchd 잡은 이 워킹 트리에서 그대로 돈다 — 브랜치를 체크아웃한 채로 두면 그 코드가 금요일에 실행된다.

```
① 사람: 키체인 등록 2건 (§1)        ← 안 하면 ②부터 전부 실패
② 사람: 등록 확인 (§1 하단)
③ plist 재적재 — 부팅 로그 경로 반영
     launchctl bootout  gui/$(id -u)/com.weeklystocks.pipeline
     launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.weeklystocks.pipeline.plist
④ 브랜치 병합 후 main 체크아웃
⑤ config.yaml 평문 3줄 삭제 (kis.app_key · kis.app_secret · ai.api_key)
⑥ §4 검증 ①~⑥ 전부 통과 확인
```

**①이 끝나기 전에는 워킹 트리를 `main` 에 두어야 한다.** 그래야 금요일 잡이 기존 평문 경로로 정상 실행된다.
