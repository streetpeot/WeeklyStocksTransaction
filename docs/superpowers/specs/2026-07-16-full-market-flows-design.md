- 작성: 2026-07-16 (검토 메모 `docs/전종목수급_검토메모_20260713.md` 후속 — 구현 완료 시 메모 삭제)
- 로드맵: 볼트 `wiki/topics/개발/자동화 로드맵.md` 「전종목 수급 확보」 (우선순위 Top5 #4)
- 상태: 설계 승인 완료 (2026-07-16), 구현 계획 수립 대기

## 1. 배경과 목표

현행 파이프라인은 시총·주가·등락률은 전종목(~4,220개)을 수집하지만, 기관·외국인 수급은
Naver 상세 크롤 대상인 **시총 상위 200종목**에 한정된다(`modules/crawler.py` §6, `df.head(200)`).
이로 인해 (1) 볼트 엔티티 중소형주의 수급 추적 불가 (2) 소형주 밀집 섹터의 수급 집계 왜곡
(3) 중소형 로테이션 서술의 근거 부족 (4) 전종목 수급 이력 자산 부재.

**목표**: 전종목 기관·외국인 주간 순매수를 확보하고, 사용자 워치리스트 종목의 수급을
매주 자동 추적하며, 보고서를 개인용/공유용으로 이원화한다.

## 2. 사전 조사에서 확정된 사실 (2026-07-16 라이브 검증)

- **pykrx 일괄 API 존재**: `stock.get_market_net_purchases_of_equities_by_ticker(fromdate, todate, market, investor)`
  — KRX [12010] 투자자별 순매수상위종목. 반환: 티커/종목명/매도·매수·순매수 거래량·**거래대금**.
  `fromdate~todate`로 KRX가 기간 집계 → 주간치를 시장×투자자당 1콜. 투자자 코드에
  `기관합계(7050)`·`외국인(9000)` 존재(연기금·투신 등 세분류도 동일 API).
- **KRX 로그인 요구 (신규 장애물)**: KRX가 익명 프로그래매틱 접근을 차단(`LOGOUT` 응답).
  현재 설치된 pykrx 1.2.4는 대응 없음 → **이 머신에서 pykrx 호출 전부 실패 중**
  (7/13 세션의 'Logging error' 노이즈의 원인으로 추정). pykrx 1.2.8(2026-05-04)은
  `KRX_ID`/`KRX_PW` 환경변수 로그인(JSESSIONID 세션, 1시간 만료 자동 갱신,
  CD010=비밀번호 변경 요구, CD011=중복 로그인 처리)으로 대응.
- **publisher 영향**: `modules/publisher.py`의 `_krx_trading_days`(Friday-lag 체크)도 같은
  이유로 현재 항상 실패 → 달력 폴백으로 동작 중. pykrx 1.2.8 + 자격증명이면 함께 복구됨.
- **B안(Naver 순회 확장) 실측 비용**: 현행 200종목당 136초(7/10 로그) → 4,224종목 순차 ≈ 48분.
  A안(4콜) 채택으로 배제.

## 3. 사용자 결정 사항 (2026-07-16 브레인스토밍)

1. **A안(KRX 일괄) 채택** — KRX 계정 생성 수용. 단점(정책 재변경 리스크·비밀번호 만료·
   계정 제재 가능성) 논의 완료 → 폴백 내장으로 완화.
2. **워치리스트는 볼트에서 관리** — 볼트 엔티티 유무와 무관하게 "현재 보고 있거나 보유한
   기업"을 사용자가 직접 관리. `wiki/topics/개인/워치리스트.md` 신설.
3. **보고서 이원화** — 개인용(워치리스트 섹션 포함)과 공유용(수집만 기반). 두 보고서의
   차이는 워치리스트 섹션 유무뿐이어야 하며, **나머지 섹션의 문맥에 워치리스트가
   나타나서는 안 된다**.
4. **배포 라우팅** — 개인용 → 볼트 반입 + 텔레그램 DM / 공유용 → 기존 텔레그램 채널.

## 4. 설계

### §4.1 데이터 수집 — KRX 일괄 + 현행 폴백

- pykrx `1.2.4` → `1.2.8` (requirements 갱신).
- **자격증명**: 사용자가 data.krx.co.kr 무료 가입(전제조건). ID/PW는 macOS 키체인 보관
  (서비스명 예: `krx-data`, 선례 `telegram-bot-memtrack`) → 파이프라인 시작 시 `security` CLI로
  읽어 `KRX_ID`/`KRX_PW` 환경변수 주입. config.yaml 평문 금지.
- crawler 신규 함수 `crawl_krx_investor_flows(fromdate, todate)`:
  {KOSPI, KOSDAQ} × {기관합계, 외국인} = **주 4콜** → 전종목 `1주기관매매`/`1주외국인매매`(억원, 거래대금 기준).
- **소스 혼용 금지**: KRX 성공 시 수급 컬럼은 상위 200 포함 전부 KRX 값으로 통일.
  Naver 상세 크롤은 유지하되 재무·PBR·배당 용도로만 사용(투자자 컬럼 미사용).
  KRX 실패(로그인 실패·빈 응답·예외) 시 → 현행 Naver 투자자 값으로 자동 폴백 + 경고 로그 + 텔레그램 DM 통지.
  어느 주든 수급 소스는 정확히 하나.
- pykrx 1.2.8은 로그인 ID를 stdout에 print — 로그 위생 확인(마스킹 또는 수용 판단)을 구현 시 포함.

### §4.2 검증 게이트 (구현 첫 단계 — 통과 전 본 구현 착수 금지)

계정 확보 후 실호출로 확인:
1. **전종목 반환 여부** — API 원천 화면명이 "순매수상위종목"이라 상위 N 제한 가능성 잔존.
2. **금 20시 데이터 반영** — 금요일분이 20시 조회에 포함되는지(미포함 시 주간치가 월~목로 잘림).
3. **값 정합성** — 현행 Naver 값과 표본 대조(기관 분류 기준·억원 환산 차이 파악).

불성립 시: 구현 중단, C안(워치리스트 종목만 KIS/Naver 추가 조회) 후퇴를 사용자와 재논의.

### §4.3 워치리스트 — 볼트 파일

- 경로: `wiki/topics/개인/워치리스트.md` (frontmatter 표준: type: topic, tags: [개인]).
- 본문 markdown 표: `티커 | 종목명 | 구분(보유/관심) | 메모`. WST는 **티커 열만** 파싱.
- WST config에 `watchlist_path` 추가. 파일 없음/파싱 실패/빈 목록 → 워치리스트 섹션만
  생략하고 파이프라인 계속(경고 로그).

### §4.4 보고서 이원화

- **공유용** = 현행 [6/6] LLM 보고서 그대로. 파일명 `주가자금동향_YYYYMMDD.md`,
  frontmatter·차트 파일명(`*_기준일.png`) 계약 불변.
- **개인용** = 공유용 본문 텍스트 재사용 + 「워치리스트 수급」 섹션 삽입.
  파일명 `주가자금동향_개인_YYYYMMDD.md` (publisher의 `_(\d{8})\.md$` 기준일 추출과 호환).
- **문맥 격리는 구조로 보장**: 워치리스트 데이터는 reporter의 `_build_data_context`/LLM
  프롬프트에 진입하지 않는다. 개인용은 공유용 생성 후 후처리로 섹션을 삽입하므로
  공통부는 바이트 단위 동일.
- 워치리스트 섹션 = **결정적 테이블(LLM 미사용)**: 종목별 주간 기관/외국인 순매수·
  1주 등락률·시총·시총대비 수급 비중 + history.db 기반 최근 4주 수급 추이.
  (섹션 코멘터리가 필요해지면 2단계에서 워치리스트 데이터만 넣은 별도 LLM 호출로.)
- 초기 한계(수용): 상위 200 밖 종목의 4주 추이는 전종목 이력이 쌓이기 전까지 빈 칸으로
  표시("-"), 4주 후부터 완전해진다.
- 의도된 부수 변화: 수급 TOP 테이블이 "상위 200 중 TOP20" → "전종목 중 TOP20",
  섹터 수급 집계가 전종목 기준으로 정확해짐.

### §4.5 발행 라우팅 (publisher 확장)

- 공유용 → 기존 채널 PDF 전송(현행 유지).
- 개인용 → 볼트 반입(vault_ingest — 현행 반입 대상을 개인용으로 교체, 볼트 내 명칭은
  현행 규칙 `국내증시 자금동향_주간범위` 그대로 유지) + DM PDF 전송.
- 실행 시간 영향: KRX 4콜 + 테이블 조립 — 20시 파이프라인 지연 사실상 없음.

### §4.6 history.db

- `weekly_stock`에 전종목 저장(주당 ~200행 → ~4,200행/전체, SQLite 무리 없음).
- `flow_source` 컬럼(krx/naver) 추가 — 수급 값 기준 전환(Naver 주수×현재가 환산 →
  KRX 거래대금)으로 생기는 시계열 단절을 데이터에 명시. 기존 행은 naver로 소급 표기.

## 5. 제약 (발행 자동화와의 경계 — 검토 메모 §4 승계)

- **작업 디렉토리는 launchd 프로덕션** — 체크아웃 전환 금지. 구현은 **git worktree**의
  feature 브랜치에서 진행하고, **2026-07-17(금) 20시 발행 자동화 첫 무인 실행 성공이
  확인된 뒤에만 main 병합**.
- 발행 계약 불변: 보고서 파일명·frontmatter·차트 파일명 패턴. `tests/` 전체 스위트 상시 통과.
- 테스트 규약: `PYTHONPATH=".venv/lib/python3.11/site-packages:." /opt/homebrew/bin/python3.11 -m pytest tests/ -v`
- 시크릿: config.yaml·.kis_token_cache.json gitignore 유지, KRX 자격증명은 키체인만.

## 6. 테스트 계획

- KRX 수집: 성공/빈 응답/예외 → 폴백 분기 (pykrx mock).
- 워치리스트: 정상 파싱/파일 없음/표 형식 오류/빈 목록.
- 이원화: 공유용-개인용 공통부 동일성, 워치리스트 섹션 삽입 위치, LLM 프롬프트에
  워치리스트 미포함 검증.
- 발행 라우팅: 채널=공유용, DM+볼트=개인용.
- history.db: flow_source 기록, 전종목 행 수.

## 7. 수용 기준

1. 금 20시 무인 실행에서 전종목(~4,200개) 수급이 KRX로 수집되고 history.db에 적재된다.
2. 공유용 보고서가 현행 계약대로 채널에 전송되고, 워치리스트 흔적이 없다.
3. 개인용 보고서가 워치리스트 섹션을 포함해 볼트 반입 + DM 전송된다.
4. KRX 실패 주에는 Naver 폴백으로 보고서가 정상 발행되고 DM 경고가 온다.
5. 기존 테스트 24건 + 신규 테스트 전체 통과.
